How this maps to the app

architecture

The scene declares items and widgets as data. It never builds UI itself, which keeps the TV and the private scenes free of panel code.

// physarum2.ts items: [{ id: "strains", count: 4, codes: ["PP-A1", "PP-B2", "PP-C3", "PP-D4"], nicknames: ["Highway", "Mesh", "Spotter", "Labyrinth"], params: [ { key: "nutrient", label: "Nutrient", drive: { perItem: ["level.low", "level.mid", "level.high", "level.all"] } }, { key: "sensor", label: "Sensor range" }, { key: "turn", label: "Turn angle" }, { key: "speed", label: "Speed" }, { key: "excitability", label: "Excitability", drive: {…} }, { key: "stain", label: "Stain", kind: "hue" }, ], }], panel: [ { widget: "strainBoxes", items: "strains" }, { widget: "relationWeb", items: "strains", key: "att", presets: {…} }, { widget: "seedPad", keys: { share: "dose", spread: "spread" } }, { widget: "labLog" }, ],

  • Nothing downstream changes. Every strain control becomes an ordinary keyed setting, so stimuli, Auto, saved Looks and share links work on day one.
  • Widgets are reusable. They live in one registry in the panel code. relationWeb could edit Gates' object pairs, seedPad could place Petri drops or Powder emitters, and strainBoxes could hold Kaleidoscope layers.
  • The standard row is the building block. Every row inside a widget is the same slider, readout and stimulus chip used everywhere else, so there is one way to wire music to anything.
